# Harden, chunk, then hybridize: Argosy's roadmap

Argosy's core design is sound. It has git-native, local-first knowledge books, stable `argosy://` URIs, a careful path-contained write layer and about 500 tests. Three things hold it back: security gaps in the code and review tools, a retrieval pipeline that 2026 practice regards as a weak baseline, and a styleguide reviewer that is pure LLM judgment with nothing deterministic underneath. **Fix these first:** git option injection in `start_review`, code tools that accept any absolute path, and imports whose integrity is never checked and whose trust tier they declare themselves. Together these let a malicious shared book steer an agent into writing files outside the project. **On retrieval,** Argosy embeds each concept once with all-MiniLM-L6-v2 and truncates at 256 tokens, with no chunking, no BM25 and no reranker. Heading-based chunking with a breadcrumb prefix, plus SQLite FTS5 fused with the existing sqlite-vec index by Reciprocal Rank Fusion (RRF), is cheap and fits the current store. It is also the change most strongly backed by published evidence. **On review,** the `pattern` and `priority` fields already in rule frontmatter are dead code. Wiring them into a deterministic pre-pass, checking findings against the diff, and exporting SARIF or reviewdog output would move Argosy from "a prompt" to "a review engine". **On platform,** a lean default toolset, `outputSchema`, resource templates and pinned imports are near-term wins. A stateless Streamable HTTP endpoint built against MCP spec 2026-07-28 is the strategic bet that would let Argosy compete with hosted docs servers. The audit behind this report is a static reading of commit `245d44c` (v0.7.0). Nothing was compiled or run, and GitHub issues and PRs could not be accessed, so some of these items may already be tracked.

## (a) Three file-write paths and a self-declared trust tier need fixing first

### Confirmed by reading

**Fixed:** `start_review` now refuses `-`-prefixed `base`/`commit` and resolves every revision expression through `git rev-parse --verify --end-of-options` first — single revisions (commit, branch, tag, or tree) to their object SHA, and ranges (`a..b`, merge-base `a...b`) to SHA-only range form. Only a verified hex object id ever reaches `git diff`/`git show`, so the reviewer's full input surface survives. The original audit finding follows.

**Git option injection in `start_review`** is the most urgent defect. The `base` and `commit` parameters go to `git diff` and `git show` as positional arguments *before* the `--` separator, and the only checks are non-emptiness and mutual exclusion ([review.rs L228-254](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/codetools/review.rs#L228-L254), [L622-683](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/codetools/review.rs#L622-L683)). A value such as `--output=/some/path` would be parsed as a git option, and `git diff --output` writes to that file. `pull` already guards against exactly this by refusing leading-dash URLs ([pull.rs L178-190](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/pull.rs#L178-L190)), so the fix is to reuse that guard. Reject a leading `-`, resolve the value with `git rev-parse --verify --end-of-options <rev>^{commit}`, and pass the resolved SHA. Effort **S**. Impact: high, because the tool is reachable by any caller, including a model that imported content has prompt-injected.

**Fixed:** every code tool now resolves its path arguments through a workspace-root containment check (`resolve_path` anchors relative paths to the root, then requires the canonicalized path to stay inside it — symlinks cannot hop the boundary), with `code_tools { allow_external_paths = true }` in the user config as the explicit opt-out. The stale-write guard now fails closed: a file on disk with no recorded read is refused with an actionable message instead of silently allowed; only a missing file (whose write creates it) may be written unread. The original audit finding follows.

**Code tools are not confined to the workspace.** `resolve_path` expands `~` and passes absolute paths through unchanged; only relative paths are anchored to the project directory ([codetools/mod.rs L133-155](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/codetools/mod.rs#L133-L155)). Every code tool calls it, including the two that write: [zoom.rs L45](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/codetools/zoom.rs#L45), [astgrep.rs L82](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/codetools/astgrep.rs#L82) and [conflicts.rs L56](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/codetools/conflicts.rs#L56). This contradicts the server instructions, which say these tools work "over the workspace directory it was spawned in" ([server.rs L123-131](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/mcp/server.rs#L123-L131)). The fix is to canonicalize and require `starts_with(project_root)`, the same defensive check the knowledge write path already does ([local/ops.rs L98-146](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/local/ops.rs#L98-L146)). Expose an explicit config opt-out for anyone who wants absolute paths. Effort **S–M**.

**Fixed** (same change): `check_before_edit` now refuses a file on disk with no recorded read ("no read on record: … read it through these tools first"), instead of returning `Ok(())`. Only a missing file is allowed unread — the write creates it, so nothing is clobbered. The original audit finding follows.

Compounding this, **the stale-write guard fails open**. `check_before_edit` returns `Ok(())` for a file that was never read, so `astgrep apply` and `conflicts resolve` can overwrite files the agent never looked at ([file_tracker.rs L50-60](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/codetools/file_tracker.rs#L50)). Make it fail closed, or require a read hash as an explicit parameter. Effort **S**.

**Imports are trusted on their own say-so.** `validate_integrity` exists, but only tests call it; neither `pull` nor session open does ([archive.rs L250-332](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/package/archive.rs#L250-L332)). Separately, `verified_tier` returns whatever the concept's own `verified` frontmatter says, so an imported book can label itself `human-reviewed` ([reports.rs L240-245](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/mcp/reports.rs#L240-L245)). That makes the spec's trust-tier language ([specification.md L423](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/docs/specification.md#L423)) effectively decorative. Verify the sidecar whenever one is present. Then cap an imported concept's effective tier at the import's tier, which local config sets (for example, an allowlist of trusted remotes or signer keys), never at the concept's self-claim. Effort **M**. This matters because research on RAG poisoning shows that **five crafted texts per target question achieved about 90% attack success** against knowledge bases of millions of texts ([Reco, citing PoisonedRAG](https://www.reco.ai/blog/rag-poisoning)). The broader MCP threat record now includes rug-pull CVEs such as CVE-2025-54136 and a malicious registry server ([CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-mcp-tool-poisoning-ai-agent-exfiltration-2/)).

**Shared content reaches the agent without provenance labels.** Imported concepts, skills and Good/Bad sections are returned verbatim ([session.rs L345-409](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/mcp/session.rs#L345-L409)). `search_rules` hits carry the book name, but neither the local/imported kind nor the trust tier ([reports.rs L13-48](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/mcp/reports.rs#L13-L48)). The only defense is advisory text in the server instructions ([server.rs L98-110](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/mcp/server.rs#L98-L110)). Add `kind`, `trust` and source commit to every hit and read result. Wrap imported bodies in explicit "untrusted document content" delimiters, and strip or flag zero-width and invisible Unicode at index time; both are standard RAG-poisoning defenses ([Reco](https://www.reco.ai/blog/rag-poisoning)). Effort **S**. Simon Willison's "lethal trifecta" framing applies directly ([Willison](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/)). Shared books are the untrusted content, the project tree is the private data, and the unconfined write tools above complete the set. Fixing the first three items breaks the chain.

**Sessions never go away.** Review sessions sit in a `HashMap` that nothing ever removes from, and each one can hold a 2 MiB diff ([review.rs L175-186](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/codetools/review.rs#L175-L186)). Project sessions, each with an open SQLite connection and an embedding provider, are cached for the life of the process, so imports pulled after a session opens stay invisible until restart ([session.rs L43-49](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/mcp/session.rs#L43-L49)). Add TTL/LRU eviction, and re-run reconcile on a cheap trigger such as an mtime check or a `refresh` tool. Effort **S–M**.

**`report_finding` checks only that `rule_uris` start with `argosy://`.** It does not check that they resolve, or that `path` is in the snapshot's `changed_files` ([review.rs L335-352](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/codetools/review.rs#L335-L352), [L529-534](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/codetools/review.rs#L529-L534)). An agent can therefore cite invented rules and files. Return `isError: true` with an actionable message so the model can self-correct, which the MCP tools spec recommends for business errors ([MCP spec, Tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)). Effort **S**.

Two lower-severity items round this out. **Dead fields:** `pattern`, `priority` and `rule_id` in rule frontmatter are never read ([styleguide.rs L122-135](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/styleguide.rs#L122-L135)); section (c) turns them into features. **A stale doc comment** promises resource templates that `list_resource_templates` does not implement ([session.rs L630-633](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/mcp/session.rs#L630-L633)); section (d) covers implementing them.

## (b) One 256-token vector per concept leaves most long documents unsearchable

Argosy's retrieval stack is one embedding per concept. The embedded text is the description plus the body ([index/mod.rs L612-619](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/index/mod.rs#L612-L619)), embedded by all-MiniLM-L6-v2 and **silently truncated at 256 tokens** ([tract.rs L49-50](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/index/tract.rs#L49-L50)), then searched by brute-force sqlite-vec KNN. There is no lexical search, no chunking (`chunk_ordinal` is always 0, [index/mod.rs L79-99](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/index/mod.rs#L79-L99)), no passage text in hits ([reports.rs L13-48](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/mcp/reports.rs#L13-L48)) and no local reranker. Each choice was reasonable for a v0. Together, though, they mean an `architecture` document is represented by roughly its first 150–200 words, and a query for an exact rule ID or error code depends on semantic luck. The project's own benchmark says it is "a drift detector, not a relevance-labeled search-quality evaluation" ([embedding-results.md](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/benches/embedding-results.md)), so nobody currently knows how good retrieval is.

**Build the eval first (effort S–M).** The cheapest effective harness is a JSON file of queries mapped to expected `argosy://` URIs, scored with recall@k and MRR in CI. Bootstrap it by having an LLM write questions per section, then prune them by hand. Anthropic uses recall@20 (reported as failure rate) as its headline retrieval metric ([Anthropic](https://anthropic.com/news/contextual-retrieval)), and Elastic's guidance is to compare BM25, dense and fused retrieval on your own data ([Elastic](https://www.elastic.co/search-labs/blog/improving-information-retrieval-elastic-stack-hybrid)). The competitor docs-mcp-server already ships a search-quality benchmark ([arabold/docs-mcp-server](https://github.com/arabold/docs-mcp-server)), so publishing one also helps positioning. Include stale-content and deleted-content challenge queries, as Oracle recommends for index-drift detection ([Oracle](https://blogs.oracle.com/developers/how-to-detect-rag-index-drift-deleted-docs-stale-chunks-and-duplicate-embeddings)).

**Chunk by heading, with context (effort M; high impact).** The evidence-backed default is structure-aware recursive splitting: split on headings, then recursively within sections at about 256–512 tokens with 10–20% overlap, and leave short concepts whole. On realistic documents this beat semantic chunking: one benchmark reports 69% answer accuracy for recursive 512-token chunks against 54% for semantic chunking ([PremAI benchmark summary](https://www.premai.io/blog/rag-chunking-strategies-the-2026-benchmark-guide/)). The `chunk_ordinal` column already exists for this. Prefix each chunk with the concept title and heading breadcrumb, and use that prefixed text both for embedding and for BM25. This is a deterministic, no-LLM version of Anthropic's Contextual Retrieval. The full LLM-generated version **cut top-20 retrieval failures by 35% with contextual embeddings, 49% with contextual BM25 added, and 67% with reranking added** ([Anthropic](https://anthropic.com/news/contextual-retrieval)). No benchmark isolates how much of that gain the cheap breadcrumb-only version captures. The eval should answer that before Argosy pays for LLM-generated prefixes, which could run as an optional `argosy index --contextualize`. Hits should then return the matched passage, its heading path and a line range, so the agent can skip a second `read`. Add `read` with a section or line-range parameter for small-to-big expansion.

**Add FTS5 BM25 and fuse with RRF (effort M; high impact).** In Elastic's BEIR experiments, RRF over BM25 plus a learned sparse model beat the sparse model alone by 1.4% and BM25 alone by 18% NDCG@10. It never lost to BM25, and it needs no tuning; tuned linear blends do better only with labeled queries ([Elastic](https://www.elastic.co/search-labs/blog/improving-information-retrieval-elastic-stack-hybrid)). RRF over sqlite-vec plus FTS5 can be written as a single SQL query ([Simon Willison](https://simonwillison.net/2024/Oct/4/hybrid-full-text-search-and-vector-search-with-sqlite/)), so Argosy keeps its one-file SQLite store. This also gives a zero-model mode: BM25-only search works before or without the 90 MB download, removing the first-run stall. Agent-search research supports the lexical leg. Claude Code moved from a vector DB to agentic search ([SmartScope](https://smartscope.blog/en/ai-development/practices/rag-debate-agentic-search-code-exploration/)), and Augment found grep sufficient for SWE-bench ([jxnl.co](https://jxnl.co/writing/2025/09/11/why-grep-beat-embeddings-in-our-swe-bench-agent-lessons-from-augment/)). Both sources still credit embeddings for unstructured prose, which is most of what a knowledge book holds. Hybrid search is the right answer for Argosy, not grep-only. An exact-phrase or regex `grep` mode on `search` is a cheap complement.

**Replace the default embedder (effort S–M).** all-MiniLM-L6-v2 scores 56.3 on MTEB and appears on vendor lists as "not recommended for production" ([PremAI embeddings](https://www.premai.io/blog/best-embedding-models-for-rag-2026-ranked-by-mteb-score-cost-and-self-hosting/)). These are vendor figures, so re-verify them on the live leaderboard. EmbeddingGemma (about 308M parameters, 2k context, 768 dimensions with Matryoshka truncation to 256, under 200 MB RAM quantized) is the natural local default ([Hugging Face](https://huggingface.co/blog/embeddinggemma)). nomic-embed-text-v1.5 (Apache 2.0, 8k context) is the alternative. Both fit the existing tract-onnx path. EmbeddingGemma needs task prefixes, much like the BGE query instruction Argosy already handles ([tract.rs L60-74](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/index/tract.rs#L60-L74)). Truncating to 256–512 dimensions keeps brute-force search fast: one benchmark measured 68 ms for a full scan of 100k 384-dimension vectors ([Bambini](https://marcobambini.substack.com/p/the-state-of-vector-search-in-sqlite)). Model identity is already tracked and triggers a full rebuild ([index/mod.rs L582-597](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/index/mod.rs#L582-L597)), so migration is cheap. An optional hosted provider (Voyage, Gemini) would serve teams that prefer quality to locality.

**Add a local cross-encoder reranker (effort M; medium-high impact).** Today's only reranker is the external "Jev" decision endpoint ([decision/mod.rs](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/decision/mod.rs#L1-L30)), which most users will never run. In the Agentic RAG study, an explicit reranker selected documents more reliably than letting the agent re-query: 49.5 against 43.9 on document refinement, with agents re-retrieving in only about 10% of cases. The authors recommend a reranker even in agentic pipelines ([arXiv 2601.07711](https://arxiv.org/pdf/2601.07711)). bge-reranker-v2-m3 and mxbai-rerank are permissively licensed options ([FutureAGI](https://futureagi.com/blog/best-rerankers-for-rag-2026/)). Keep Jev as a pluggable backend behind the same trait.

**Smaller items.** Add `updated_at`, content hash and source commit to `UnitMeta`, which today stores no timestamps ([index/mod.rs L52-64](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/index/mod.rs#L52-L64)), and return them in hits so agents can judge freshness. Collapse results by concept so one long document cannot crowd the top-k. Store per-book and per-document summaries as retrievable units for "overview" queries; a lite version of the RAPTOR result, where tree and summary retrievers scored 38.5% against 20–22% for chunk retrievers on cross-chunk questions ([arXiv 2501.01880](https://arxiv.org/pdf/2501.01880)). The `scan` prompt already writes `document/summary`, so this is mostly indexing policy. Expose explicit links and tags as `related`/`backlinks` navigation rather than building a GraphRAG pipeline. Graph methods win on multi-hop questions but lose to plain RAG with reranking on simple lookups, at many times the token cost ([GraphRAG-Bench](https://arxiv.org/html/2506.05690v3)). Skip server-side HyDE or multi-query: the calling agent already rewrites queries, and the agentic-RAG study found agent rewriting the strongest option at 55.6 NDCG@10 ([arXiv 2601.07711](https://arxiv.org/pdf/2601.07711)). Last, point out to users that a book under about 200k tokens can simply be loaded whole with prompt caching ([Anthropic](https://anthropic.com/news/contextual-retrieval)). A `read_all`/`llms-full.txt` export serves that case cheaply.

## (c) The reviewer is a prompt; dead frontmatter fields can make it an engine

Review today is entirely LLM-driven. `start_review` snapshots a diff, `REVIEWER_PROMPT` tells the agent to call `search_rules` and report P0–P3 findings ([harness.rs L136-221](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/harness.rs#L136)), and findings live in memory with no export and no apply path ([review.rs L175-186](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/codetools/review.rs#L175-L186)). Practitioner and research evidence agree that this is the weakest configuration. PostHog says LLMs are unreliable linters and recommends Vale for detection and LLMs for fixing ([PostHog](https://posthog.com/handbook/docs-and-wizard/vale)). The Checkstyle+ paper sent only the 9 semantic rules to an LLM and left the rest to Checkstyle, lifting **recall from 0.73 to 0.99 at precision 0.99**. It also found run-to-run agreement of only 55% once discretionary warnings were included, so the nondeterminism concentrates in judgment calls ([arXiv 2510.23068](https://arxiv.org/pdf/2510.23068)). CLASE found an LLM judge alone correlated at r = 0.317 with experts, against 0.827 for a fused objective-plus-LLM score ([arXiv 2602.12639](https://arxiv.org/html/2602.12639v1)). Both studies are narrow (competitive-programming Java; Chinese legal text), but they point the same way.

**Deterministic pre-pass from `pattern` (effort M; high impact).** Give rules a `check` type of `regex`, `astgrep`, `vocab` or `llm`. Run the deterministic types over the added lines of the snapshot, using the `astgrep` engine Argosy already has. Emit findings with exact line ranges and confidence 1.0, then hand only `llm` rules to the agent. Vale's typed rules (`existence`, `substitution` with a `swap` map, `vocab` accept/reject lists) are a proven vocabulary to copy ([Vale custom styles](https://mintlify.wiki/errata-ai/vale/guides/custom-styles)). Where a project already has `.vale.ini` or a textlint config, shell out to it and merge the alerts rather than reimplementing them. textlint even ships a first-party MCP mode ([textlint MCP](https://textlint.org/docs/mcp)).

**Grounding and verification (effort S–M).** Beyond the `rule_uris` and `path` validation in section (a), require each LLM finding to quote a span that exists verbatim in the snapshot. Demote findings whose rule has `enforcement: judgment` to P3 suggestions. Claude Code Review runs a dedicated verification step to filter false positives before posting ([Claude Code Review docs](https://code.claude.com/docs/en/code-review.md)), and the decision endpoint could serve as an optional verifier. Fix the `rerank_rules` payload so applicability is judged against the actual hunk (see "Needs a test" above). Pass rule `priority` and trust tier into `search_rules` hits so the reviewer can weight a local `error` rule above an imported `info` rule.

**Richer rule schema and a guide linter (effort M).** Successful systems all rewrote prose guides into atomic, testable rules. Apollo found that pasting a human guide into a review prompt produced invented rules and vague feedback; concrete do/don't pairs with stated reasons fixed it ([Apollo](https://www.apollographql.com/blog/engineering/how-we-taught-an-ai-to-nitpick-docs)). GitBook separates numbered, enforceable rules from unnumbered judgment, never reuses IDs, and keeps placeholder rules inactive ([GitBook](https://gitbook.com/docs/create-content/styleguide.md)). The proposed frontmatter adds `enforcement` (must/should/judgment), `default_severity`, `applies_to` globs, `check`, `exceptions`, `status` (draft/active/deprecated) and `source`. Add an `argosy validate --styleguide` lint that warns when a rule lacks a Bad example, a reason or a scope. `applies_to` globs let `search_rules` pre-filter by changed path before semantic ranking, which is the scoping model of Copilot's `applyTo` and CodeRabbit's path instructions ([GitHub](https://github.blog/changelog/2025-09-03-copilot-code-review-path-scoped-custom-instruction-file-support), [CodeRabbit](https://docs.coderabbit.ai/knowledge-base/code-guidelines)).

**Good/Bad examples as a regression suite (effort S–M; high leverage).** Each rule's Bad example must trigger it and each Good example must not. An `argosy test styleguide` command can report per-rule false positives on Good examples, recall on Bad examples, and stability across repeated runs. This mirrors PostHog's per-rule Vale fixtures ([PostHog](https://posthog.com/handbook/docs-and-wizard/vale)). It would also give Argosy a precision number, which none of the published docs reviewers report.

**Review policy separate from rules (effort S).** Claude Code distinguishes REVIEW.md (severity calibration, nit caps, skip paths, "CI already enforces this", re-review convergence) from general guidance, and warns that "a long REVIEW.md dilutes the rules that matter most" ([Claude Code Review docs](https://code.claude.com/docs/en/code-review.md)). GitBook caps reviews at five flags ([GitBook](https://gitbook.com/docs/create-content/styleguide.md)), and Progress warns that once users find output noisy, they stop using it ([Progress](https://www.progress.com/blogs/building-an-ai-powered-self-review-skill)). A `styleguide/_policy` concept with `max_nits`, `skip`, severity definitions and per-rule enable/disable or severity overrides fills the configurability gap. Today the only knobs are language/category filters and `focus` ([prompts.rs L122-127](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/mcp/prompts.rs#L122-L127)). Add an `overrides: argosy://base/styleguide/<id>` field so a local book can disable or re-grade an imported rule. That gives Vale-style `BasedOnStyles` layering with traceable inheritance ([Vale](https://mintlify.wiki/errata-ai/vale/guides/custom-styles)).

**Output that reaches PRs (effort M; high impact).** Add `review_findings format=sarif|rdjsonl` and an `argosy review export` CLI. Map each finding to a SARIF result: `ruleId` is the argosy URI, `level` comes from P0–P3, the region from the line range, and `fixes[]` from a new structured `{range, replacement}` edit field. reviewdog accepts SARIF and rdjson and posts one-click suggestions through its `github-pr-review` and `gitlab-mr-discussion` reporters, though not through check annotations ([reviewdog](https://github.com/reviewdog/reviewdog)). Persist findings to the state directory so they survive restart. Add a `suggest_fix` tool that returns fixed content without writing it, following textlint's `getLintFixedTextContent` ([textlint MCP](https://textlint.org/docs/mcp)); the reviewer stays read-only and the human applies. Emit a severity-count summary JSON that CI can gate on, as Claude Code Review does ([Claude Code Review docs](https://code.claude.com/docs/en/code-review.md)).

**Finer review units and interop (effort M).** Apollo reviewed each added line with ±5 lines of context, skipping code blocks and frontmatter, and found this "significantly more accurate" than whole-file review ([Apollo](https://www.apollographql.com/blog/engineering/how-we-taught-an-ai-to-nitpick-docs)). `review_diff` could therefore hand out hunk-level work items, each paired with the top-k rules for that path. Two more items fit here. First, add a "pre-existing" flag for violations outside the diff. Second, add import and export between Argosy rules and the files agents already read: CLAUDE.md, AGENTS.md, `.github/instructions/*.instructions.md` and `.cursor/rules`. CodeRabbit already ingests all of them ([CodeRabbit](https://docs.coderabbit.ai/knowledge-base/code-guidelines)), and agent-style shows that compiling one rule source into each tool's file works ([agent-style](https://github.com/yzhao062/agent-style)). Extending `argosy convert` to import Vale YAML would let teams start from the CC BY 4.0 Google style package ([Vale Hub](https://vale.sh/hub/google/)).

## (d) Twenty-six tools, stdio only, and unpinned git clones lag the 2026 platform

**Shrink the default tool surface (effort M; medium-high impact).** Argosy exposes 15 knowledge tools and 11 code and review tools ([tools.rs](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/mcp/tools.rs)). Peer docs servers expose two or three: Context7, Ref and DeepWiki ([upstash/context7](https://github.com/upstash/context7), [Ref](https://glama.ai/mcp/servers/ref-tools/ref-tools-mcp), [DeepWiki](https://docs.devin.ai/work-with-devin/deepwiki-mcp.md)). One report counted seven MCP servers consuming **67.3k tokens, a third of a 200k context, before any prompt** ([mcp.directory](https://mcp.directory/blog/mcp-context-bloat-fix-2026-tool-search-code-mode-progressive-disclosure)). Add toolset selection (`--toolsets knowledge,review,code`) with `knowledge` as the default. Collapse `write_memory`/`write_rule`/`write_document` into one `write` keyed by namespace, and do the same for the three deletes. Prefix names with `argosy_` and write keyword-rich descriptions so deferred tool search finds them. Anthropic's tool-design guidance adds a `response_format` concise/detailed switch, which used about a third of the tokens in its example. It also recommends pagination with "narrow your query" truncation messages and semantic identifiers rather than opaque IDs ([Anthropic](https://www.anthropic.com/engineering/writing-tools-for-agents)). Measure the schema token cost before and after.

**Conform to the tools and resources spec (effort S–M).** Today Argosy returns `structuredContent` without any `outputSchema` ([server.rs L136-142](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/mcp/server.rs#L136-L142)). Under the spec, once a schema is declared, conforming `structuredContent` is mandatory, which makes it a contract clients can rely on. Results can also carry `resource_link` items pointing to `argosy://` URIs instead of inlined bodies ([MCP spec, Tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)). Implement `argosy://{book}/{namespace}/{id}` resource templates to make the stale doc comment true. Fix resources resolving against the server's process cwd rather than the project, which the protocol cannot pass per call ([session.rs L756-764](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/mcp/session.rs#L756-L764)): include the project slug in the URI. Expose `skill/` concepts as resources, as Mintlify does with `skill.md` ([Mintlify](https://www.mintlify.com/docs/ai/model-context-protocol.md)). Argosy already emits SEP-2549 cache hints ([server.rs L29-34](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/mcp/server.rs#L29-L34)), so it is ahead of many servers on the 2026-07-28 spec. One caveat: the Rust SDK's support for that spec is still beta ([MCP blog](https://blog.modelcontextprotocol.io/posts/2026-07-28/)), and the audit did not verify what `ProtocolVersion::LATEST` resolves to in rmcp 3.5.1.

**Stay off deprecated primitives.** The 2026-07-28 spec deprecates Sampling, Roots and Logging, replaces server-initiated elicitation with Multi Round-Trip Requests, and moves Tasks into an extension ([MCP blog](https://blog.modelcontextprotocol.io/posts/2026-07-28/), [AAIF](https://aaif.io/blog/mcp-2026-07-28-whats-changing-and-how-to-migrate)). Any future server-side summarization or contextualization should call a configured model endpoint, as the decision client does, rather than use sampling. Long operations such as a full index build or a whole-repo review are good candidates for the Tasks extension once rmcp supports it. MCP Apps could render a P0–P3 review panel in hosts that support it. Argosy's `dream`/`scan`/`review` prompts carry real workflow logic. Shipping them as Agent Skills too guards against uneven client support for MCP prompts (an untested inference). The `argosy agent reviewer` installer is already halfway there ([harness.rs L81-107](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/harness.rs#L81-L107)).

**Make sharing reproducible (effort M–L; high impact for teams).** There is no `update`, `remove` or `publish` command ([cli/mod.rs L38-46](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/cli/mod.rs#L38-L46)), and `pull` refuses to overwrite an existing clone ([pull.rs L209-217](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/pull.rs#L209-L217)), so updating an import means deleting and re-pulling. Add a per-project `argosy.lock` recording URL, ref and resolved commit. `argosy update` should fetch, show the diff of `skill/` and `styleguide/` changes, and require confirmation before moving the pin. Hash-pinning plus re-review on change is the standard rug-pull mitigation ([CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-mcp-tool-poisoning-ai-agent-exfiltration-2/)). Optional signing of the integrity sidecar (Sigstore or SSH signatures) would give the trust tier a real root. Keep `memory/` excluded everywhere, including any future hosted endpoint; GitBook's note that hidden pages stay reachable through MCP shows how visibility leaks happen ([GitBook](https://gitbook.com/docs/ai-for-your-readers/mcp-servers-for-published-docs.md)).

**Interop exports (effort S–M each).** Agent Skills (SKILL.md) is now an open standard with native support across Claude Code, Codex, Copilot and Gemini CLI. Its progressive disclosure costs about 100 tokens per skill ([Noqta](https://noqta.tn/en/news/skill-md-open-standard-30-ai-coding-tools-adoption-2026)). AGENTS.md is used by more than 60,000 projects ([agents.md](https://agents.md/)). An `argosy export skills|agents-md|llms-txt` command lets a book serve clients that never install Argosy. Treat llms.txt as low priority: 97% of llms.txt files received zero requests in Ahrefs' log study ([PPC Land](https://ppc.land/llms-txt-adoption-rises-8-8x-but-97-of-files-get-zero-ai-requests/)). List Argosy in the official MCP registry under `io.github.craft-build` with a `server.json`, which is cheap discoverability ([RoxyAPI](https://roxyapi.com/blogs/mcp-registries-where-to-list-your-server-2026)).

**Remote mode (effort XL; strategic).** The stdio-only transport ([commands.rs L641-660](https://github.com/craft-build/argosy/blob/245d44ccdf8234b09edcbd3b0f02b791b73b6ac4/src/cli/commands.rs#L641-L660)) and the global lock rule out a shared team server. If Argosy goes remote, target 2026-07-28 directly: stateless Streamable HTTP, `server/discover`, the `Mcp-Method`/`Mcp-Name` routing headers, and Client ID Metadata Documents rather than Dynamic Client Registration for OAuth ([MCP blog](https://blog.modelcontextprotocol.io/posts/2026-07-28/)). Observe the spec's security MUSTs: no token passthrough (never forward user tokens to git hosts), verify every request, and no session-based auth ([MCP Security Best Practices](https://modelcontextprotocol.io/specification/2025-06-18/basic/security_best_practices)). Per-book ACLs must be enforced as SQL filters *before* ranking ([Reco](https://www.reco.ai/blog/rag-poisoning)). A read-only, per-book endpoint is the right first slice, because it needs no write ACLs and matches what Mintlify and GitBook already serve.

## (e) Argosy's niche is versioned, reviewable team knowledge, not library docs

The hosted docs-MCP field has converged on zero-install remote endpoints with tiny tool surfaces. Context7 offers resolve-then-query, DeepWiki offers structure-then-contents-then-ask, and Mintlify and GitBook give every docs site a `/mcp` endpoint ([Context7](https://github.com/upstash/context7), [DeepWiki](https://docs.devin.ai/work-with-devin/deepwiki-mcp.md), [Mintlify](https://www.mintlify.com/docs/ai/model-context-protocol.md), [GitBook](https://gitbook.com/docs/ai-for-your-readers/mcp-servers-for-published-docs.md)). These products serve *public library documentation*, and Argosy should not chase them there. Context7's January 2026 free-tier cut, which followed adding an LLM call to every request, drew a loud backlash ([DevGenius](https://blog.devgenius.io/context7-quietly-slashed-its-free-tier-by-92-16fa05ddce03)). That shows how price-sensitive metered hosted docs are, and it argues for a free, local OSS core with optional hosting.

The open lane is *team-authored, versioned knowledge with review semantics*. A book bundles curated documents, skills, private memory and enforceable styleguide rules. It is shared through git with integrity metadata and applied in code review against a diff. No surveyed competitor combines those pieces. Memory servers (mem0/OpenMemory, Basic Memory) lack sharing and review ([mem0](https://mem0.ai/blog/introducing-openmemory-mcp), [Basic Memory](https://mcpmarket.com/ko/server/basic-memory)). Docs servers lack writing and rules. Style reviewers such as Markup AI ([Markup AI](https://docs.markup.ai/mcp)) and GitBook's styleguide agent are hosted and proprietary. The closest OSS analogue, docs-mcp-server, is a crawler-indexer with a benchmark and OIDC, not a knowledge-authoring system ([arabold/docs-mcp-server](https://github.com/arabold/docs-mcp-server)).

Five borrowings would sharpen that position. From Mintlify, take a `submit_feedback` tool that lets agents flag stale or wrong concepts into the local book's `memory/`, closing a quality loop that `dream` could consolidate ([Mintlify](https://www.mintlify.com/docs/ai/model-context-protocol.md)). From Ref, take an `exclude_uris` argument that deduplicates repeated searches statelessly, plus token-budgeted reads ([Ref](https://glama.ai/mcp/servers/ref-tools/ref-tools-mcp)). From Context7, take the "CLI plus skill" mode for clients that would rather not run MCP ([Context7](https://github.com/upstash/context7)). From mem0, take per-client access control on `memory/` ([mem0](https://mem0.ai/blog/introducing-openmemory-mcp)). From Claude Code Review, take bidirectional drift checking: flag diffs that contradict a `document/` or `styleguide/` concept, the way it flags PRs that make CLAUDE.md stale ([Claude Code Review docs](https://code.claude.com/docs/en/code-review.md)). That last one is the most "Argosy-shaped" feature on the list, because it uses both halves of the product at once.

The steelman against this roadmap deserves a hearing: agent harnesses are getting good enough at grep-plus-read that server-side retrieval matters less every quarter ([DAIR.AI summary of "Is Grep All You Need?"](https://academy.dair.ai/papers/is-grep-all-you-need)). That argues *for* the priorities above, not against them. Hybrid search keeps an exact-match path. Passage-level hits and section reads are agent-navigable primitives. And the defensible value moves to what grep cannot provide: provenance, trust, pinned versions, enforceable rules and PR-ready findings.

## Conclusion

The audit shifts the picture of where Argosy's risk sits. The knowledge layer is the careful part: path containment, validated concept IDs, hash-based reconcile. The exposure comes from the newer code-intel and review tools ported from Craft, which never inherited those guarantees. Shared books turn that gap from a bug into an attack chain. The fixes are mostly small, so a v0.7.x security release is achievable within days and should precede any feature work or promotion.

After that, two investments compound. A labeled retrieval eval plus Good/Bad-as-tests for rules gives Argosy numbers that none of its OSS or commercial peers publish for review precision, and lets every later change (chunking, hybrid, a new embedder, deterministic checks) be justified rather than asserted. A lockfile with pinned, verified imports turns "share via git clone" from a convenience into a supply-chain story that hosted competitors structurally cannot tell. Remote hosting can wait until both exist. When it comes, it should be stateless 2026-07-28 Streamable HTTP from day one, with no legacy transport to carry.

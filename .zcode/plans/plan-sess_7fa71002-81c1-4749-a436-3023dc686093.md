# Replace fastembed with a pure-Rust candle embedding backend

## Why this is a clean swap

fastembed is isolated behind the `EmbeddingProvider` trait and touched by exactly one source file (`src/index/fastembed.rs`). Everything else (reconcile, sqlite-vec store, MCP server) is generic over `Index<P, S>`. The model is `sentence-transformers/all-MiniLM-L6-v2` (384-dim), and tests use mocks with only ordering-based score assertions — no golden vectors — so the candle backend only needs to satisfy the trait contract.

**Scope note verified during research:** fastembed currently pulls in *two* C dependencies — onnxruntime (`ort-download-binaries`) and Oniguruma (`tokenizers`' default `onig` feature). The new chain must configure `tokenizers` with `default-features = false, features = ["fancy-regex"]` (pure-Rust regex backend) to be genuinely C-free. Candle's default CPU build is pure Rust (`default = []`, `gemm` crate). The existing bundled rusqlite C dep stays — it's the SQLite chain, not the embedding chain.

## Dependency changes (`Cargo.toml`)

Remove `fastembed`; add (all optional, wired into the existing `default-index` feature):

```toml
candle-core = { version = "0.11", optional = true }
candle-nn = { version = "0.11", optional = true }
candle-transformers = { version = "0.11", optional = true }
hf-hub = { version = "0.4", default-features = false, features = ["online", "rustls-tls"], optional = true }
tokenizers = { version = "0.23", default-features = false, features = ["fancy-regex"], optional = true }
```

`hf-hub` sync downloader with rustls = pure-Rust TLS (verify exact released feature names against hf-hub 0.4.x at implementation; goal is no OpenSSL/native-tls anywhere). GPU/accelerate features stay off by default to preserve the C-free guarantee — noted as possible opt-in follow-ups.

## New module: `src/index/candle.rs` (replaces `fastembed.rs`)

Same public shape: `CandleProvider` + `LazyCandleProvider` implementing `EmbeddingProvider`.

- **Static model spec** (the offline-identity seam): consts for repo `sentence-transformers/all-MiniLM-L6-v2`, pinned HF revision (a commit sha, chosen at implementation for reproducible weights), weight file `model.safetensors` (~90 MB), `dimensions = 384`, and `model_id() = "candle/sentence-transformers/all-MiniLM-L6-v2@candle-1"` — mirrors the old `fastembed/<model>@<backend-N>` format so the persisted-identity contract is unchanged in kind. `LazyCandleProvider::new_default` derives identity/dimensions from these consts with zero I/O (keeps MCP startup instant and offline-tolerant, same as today).
- **Model loading**: `hf_hub::api::sync` with `Cache::new(model_cache_dir())`; fetch `config.json`, `tokenizer.json`, `model.safetensors`. Parse config via `candle_transformers::models::bert::Config`; `Tokenizer::from_file`; weights via `VarBuilder::from_safetensors` from bytes (avoids the `unsafe` mmap API); `BertModel::load` on `Device::Cpu`.
- **Embedding**: batch (size ~32) `encode_batch` with truncation at 256 tokens (sentence-transformers' `max_seq_length`) and batch-longest padding; `BertModel::forward` with additive attention mask; **mean-pool over tokens weighted by the attention mask, then L2-normalize** (what fastembed/ST did internally); return one `Vec<f32>` per input, in order.
- **Cache dir**: keep the tested `cache_dir_from` precedence, renamed: `$ARGOSY_EMBED_CACHE_DIR` (new) → legacy `$FASTEMBED_CACHE_DIR` (compat fallback) → `$XDG_CACHE_HOME/argosy/embeddings` → `~/.cache/argosy/embeddings` (Windows `AppData\Local`). Old ONNX caches simply go unused.
- **Laziness**: reproduce `LazyFastembedProvider` exactly (`Mutex<Option<Inner>>`, build on first `embed`, actionable "run `argosy index build` once while online (~90 MB)" error).

## Supporting changes

- **`src/error.rs`**: `Embedding { source: fastembed::Error }` → reason-based `Embedding { reason: String }` (matches the existing `Index { reason }` style); small helper in the candle module maps candle/hf-hub/tokenizer errors into it.
- **`src/index/mod.rs`**: `pub mod fastembed` → `pub mod candle` (breaking lib API rename).
- **`src/cli/commands.rs` / `args.rs`**: rename wiring (~10 sites: `FastembedProvider`/`LazyFastembedProvider` → candle names; `SessionFactory<CandleLazy…, SqliteVecStore>`); keep the "~90 MB" user-facing copy (still accurate for the fp32 safetensors).

## Breaking changes (intentional, flag in the commit as `feat!`)

- `model_id()` changes → every existing index rebuilds once automatically on next reconcile (existing IDX-12/13 mechanism; dims stay 384, packaged `--include-index` books rebuild the same way).
- Env var `FASTEMBED_CACHE_DIR` renamed (legacy value still honored).
- Library API: `index::fastembed::{Fast,Lazy}FastembedProvider` → `index::candle::{Candle,LazyCandle}Provider`.
- Expected throughput on CPU is somewhat lower than onnxruntime (pure-Rust gemm vs. ONNX graph runtime); fine for MiniLM at argosy's doc sizes, and the trade buys build portability.
- Optional local cleanup: delete the stale untracked `.fastembed_cache/` in the repo root.
